Follow-up to 0.1.0: clearer diagnostics when the embedded engine cannot run, disk-usage control
(`reclipz cache`), a dev server, and a few maintenance fixes.

### Added

- **`reclipz cache info [--json]`** — sizes of the engine payloads, temp dir and downloads, the
  active yt-dlp version, and the retention settings.
- **`reclipz cache clean [--tmp|--engines|--downloads|--all] [--dry-run]`** — reclaim disk space:
  stale temp entries, engine versions other than the active one, and (destructive, opt-in)
  finished downloads.
- **`RECLIPZ_TMP_TTL`** (default 3600 s; `0` disables) and **`RECLIPZ_KEEP_PARTIAL`** to control
  temp-file cleanup.
- **`tools/dev.sh`** — build and run a throwaway dev server (`./.dev/{cache,downloads}`), with
  `--fixture` (local test URL), `--release`, `--no-build`, `--reset`, `--fetch`.

### Changed

- The sweeper runs every 60 s (was 300 s): finished jobs/downloads expire on schedule, and stale
  `<cache>/tmp` entries (leaked PyInstaller `_MEI*` dirs, capture files) are removed.
- Obsolete yt-dlp/ffmpeg payload versions are pruned at **startup**, not only after
  `reclipz update`.
- `HOST` / `--host` placeholders are normalised (`auto`/`localhost` → `127.0.0.1`,
  `any`/`*`/`all` → `0.0.0.0`) so a polluted environment cannot break the bind.

### Fixed

- **`Engine failed to start: FileNotFound` is now diagnosed.** That error means `execve()` failed —
  most commonly the `-musl` release running on a glibc host (its engine needs
  `/lib/ld-musl-*.so.1`) or a `noexec` cache directory. `reclipz serve` now probes
  `<engine> --version` at startup and exits with the exact hint; `reclipz selftest` and
  `reclipz yt-dlp/ffmpeg` print the same advice, and the API error reads
  `Engine failed to start (…) — run `reclipz selftest``. `RECLIPZ_SKIP_ENGINE_CHECK=1` bypasses the
  probe.
- Partial files of failed, cancelled or timed-out jobs are removed
  (`downloads/.tmp/<job>/`); previously they were left behind.
- `-Dpayload-dir=none` builds failed to compile (`error.AccessDenied` was not in the inferred error
  set of `payload.resolve`); the hint now compares `@errorName`.
- Docs: which release asset to use (gnu vs musl), checksum verification, a troubleshooting table,
  and a "Disk usage and cleanup" section.

### Upgrade

Replace the binary (same asset name as 0.1.0) and, if you run it as a service, re-run
`reclipz install-service --force` from the new binary. The engine cache and downloads are reused —
no migration needed. The embedded engine is still **yt-dlp 2026.10.26**; use `reclipz update` to
move it forward independently of reclipz.

```bash
sha256sum -c --ignore-missing SHA2-256SUMS
chmod +x reclipz-x86_64-linux-gnu
./reclipz-x86_64-linux-gnu selftest        # engine + ffmpeg smoke test
./reclipz-x86_64-linux-gnu cache info      # what is using disk
```

Release assets: `reclipz-{x86_64,aarch64}-linux-{gnu,musl}`, verified by `SHA2-256SUMS`.
Use `-gnu` on Ubuntu/Debian/Fedora/RHEL/Arch, `-musl` only on Alpine/musl systems.
